# Align internal model with webpack responsibilities

Unpack will align internal data structures and algorithms with webpack's names, phase ordering, and responsibility boundaries where practical: concepts such as `Compilation`, `ModuleGraph`, `ChunkGraph`, `ChunkGroup`, `Entrypoint`, `NormalModuleFactory`, `Dependency`, `DependenciesBlock`, `AsyncDependenciesBlock`, `DependencyTemplate`, and `RuntimeRequirement` should remain recognizable. The Rust implementation may use Rust-native traits, enums, ownership, and concurrency instead of copying webpack's JavaScript class hierarchy, mutable object layout, hook storage, or `AsyncQueue` API unless those shapes become necessary to match exposed plugin or loader behavior.

Source layout will follow the same rule for implemented responsibilities. Distinct webpack concepts and algorithms such as `Chunk`, `ChunkGroup`, `ChunkGraph`, and `buildChunkGraph` should remain separately locatable, and subsystem directories such as `dependencies`, `runtime`, and `cache` should be introduced as those implementations grow. This does not require one Rust file per JavaScript class: closed class families may remain enums, dense graph handles may index `Vec` storage, closed requirement sets may use bit sets, and hot-path set algebra may use masks instead of JavaScript-shaped `Set` or `Map` objects. Dense Rust keys use `*Handle` or `*Index` names rather than taking webpack's Module ID and Chunk ID names away from generated output identity.
