# Align top-level callback entry lifecycle

The top-level `unpack(options, callback?)` entry will validate the callback argument synchronously, then treat Compiler construction according to the selected overload. Without a callback, option validation and initialization failures remain synchronous. With a valid callback, option validation and native Compiler initialization failures return no Compiler, invoke the callback asynchronously with the error and no Stats, and never start a run. Retaining the TypeScript wrapper's `TypeError` taxonomy instead of webpack's schema `ValidationError` class and message is a narrow Documented Webpack Deviation; exact webpack validation classes and formatting are not part of this surface.

Successful construction returns the Compiler synchronously and starts the requested run, whose callback remains asynchronous. The top-level callback entry no longer closes the Compiler implicitly: the caller owns the returned Compiler, may run it again after callback delivery, and explicitly closes it when finished. Compilation Errors remain represented by Stats with a null callback error, while initialization and infrastructure failures use the callback error channel.

This decision refines ADRs 0035 and 0043, partially supersedes ADR 0055's callback-entry automatic-close rule, fully supersedes ADR 0056, and narrows ADR 0079's synchronous-validation rule to construction without a callback. The close-while-active and post-close behavior outside this top-level ownership change remains part of the broader Compiler lifecycle alignment work.
