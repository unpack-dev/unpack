# Separate compilation handles from webpack IDs

Unpack will use `ModuleHandle` and `ChunkHandle` as opaque, dense references into compilation-owned Rust storage. These Handles are compilation-local implementation details: they are not persisted and are not part of the JavaScript API. The webpack terms `ModuleId` and `ChunkId` are reserved for generated output and runtime identities. They are distinct Rust newtypes over a shared `IdValue` enum with string and `u32` variants, are assigned and stored through the Chunk Graph, participate in code generation, runtime lookup and chunk loading, and filename resolution, and remain observable through webpack-shaped JavaScript APIs such as `ChunkGraph.getModuleId` and `Chunk.id`. This preserves webpack's concepts and future JavaScript API compatibility without imitating JavaScript object identity or data structures; Rust may use indexed storage and other native ownership patterns behind those boundaries. The fixed webpack reference and refactor scope are recorded in issue #217, and the corresponding source-layout alignment landed in #218.
