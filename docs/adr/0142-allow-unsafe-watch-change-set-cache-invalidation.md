# Allow unsafe Watch Change Set cache invalidation

Unpack will keep Snapshot validation as the default source of Build Cache truth, while allowing the explicit `experiments.unsafeWatchCacheInvalidation: true` option to treat a Watch Change Set as sufficient validation for compiler-owned Memory Cache reuse during one Watch Session. When enabled, a rebuild may directly invalidate cache items whose validation inputs intersect the Watch Change Set and may reuse items outside that set without performing their ordinary Cache lookup or Snapshot validation; this deliberately accepts stale reuse and incorrect output if the watch adapter misses, misclassifies, or incompletely reports a change.

The unsafe path is limited to rebuilds triggered from an active Watch Session and must not govern an initial compilation, a manual `Watching.invalidate()` without a known change set, an ordinary `Compiler.run`, Persistent Cache restore, or reuse by a later Compiler process. Modified files, removed files, newly present missing dependencies, and changed contexts must all participate in the Watch Change Set; when no usable set is available, the implementation falls back to Snapshot validation even when the experiment is enabled. The Watch Session, N-API transport, Compiler, and Make Phase carry the model-backed change set without exposing native transport details through the public JavaScript API.

Enabling the experiment requires an active cache. When cache configuration is omitted, Unpack enables the compiler-owned Memory Cache even outside development mode; an explicit `cache: false` is rejected. The implementation may keep a same-Compiler shadow index of the most recently published Resolve and Module Build Records so it can decide reuse without entering the ordinary Cache Facade. That index is an internal acceleration layer, never a cross-process cache boundary. Each rebuild replaces its index generation and retains only records used by the immediately preceding compilation, preventing distinct-key graph churn from accumulating for the lifetime of the Compiler.

This supersedes ADR 0065 only for explicitly configured, same-Compiler Watch Session rebuilds. ADR 0065's Snapshot-validation requirement remains the rule for the default path and every non-watch or cross-process cache boundary.

The motivating Make Phase profile showed that a one-file watch rebuild still replayed 459 Factorize, Add, Build, and Process Dependencies tasks; in an optimized Callgrind run, Memory Cache lookup accounted for 13.14% of Make instructions while path comparison, hashing, sorting, allocation, and copying around record reconstruction accounted for substantially more. The project explicitly accepts this optional performance-driven deviation under ADR 0141 because the unsafe name, Watch Session boundary, fallback rules, and possible stale-output consequence keep the risk visible and contained.
